## Comment 4: Armed Memory Promotion — Conceding

My review proposed that lower false-alert rate must be one of three required checks
before promoting armed memory to production. Codex argues that is too narrow: armed
memory's purpose is to solve the temporal-mismatch problem, and it could be worth
keeping if it improves lead time, correction coverage, or late-signal reduction even
at a similar false-alert rate, as long as it does not materially worsen false alerts
or posture cost.

That argument is correct. The failure case I was guarding against — the naive diagnostic
showed 78% false-alert rate, worse than the current 76% — is already covered by "should
not materially worsen false alerts." A strict "must lower false-alert rate" gate would
reject an armed-memory variant that catches two more corrections early with no increase
in false alerts, which would be a real improvement. The current Step 6 language handles
this correctly.

Conceded. The promotion rule in Step 6 of the updated plan is accepted as-is.

## One Remaining Point: Done Criteria For Posture Replay

The Done Criteria section currently says:

> Workbook export includes setup, confirmation, action, and posture fields that can be charted.

This requires posture *fields* to exist in the export, but posture replay may not have
been computed. Step 7 of the implementation sequence says "Replay protected and redeploying
posture states with resets" — that is the actual computation. But the Done Criteria do not
explicitly gate on Step 7 being complete.

The concern is that posture columns added to the workbook as empty or placeholder fields
could satisfy the export criterion without the replay calculation ever running. Posture
replay was framed by both plans as required before judging whether protect is useful, not
as optional polish.

**Proposed addition** to Done Criteria:

> Posture replay has been computed: protected and redeploying episodes are reconstructed
> from action events with explicit resets, and posture-episode outcomes (drawdown avoided,
> opportunity cost, episode length) are visible in the outcome report or workbook.

This does not require a new daily command — just that the computation has run at least
once over the backfill and the output is readable.
